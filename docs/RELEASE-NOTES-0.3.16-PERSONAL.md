# DiPlay v0.3.16 — 视频关键线程 CPU 亲和性实验

视频 TCP 接收、ChaCha20 解密和 MediaCodec 输入线程在启动时调用 CPU 亲和性申请，目标为系统允许的全部 CPU 核心。Android cpuset、车机固件或温控仍可限制实际生效范围；DiPlay 只调整自身线程，不修改系统调度器。

已知限制：当前实现把成功结果缓存在进程内，后续线程可能直接返回缓存而不再次调用原生设置。CPU 亲和性实际按线程生效，因此诊断报告的 `Video CPU affinity: all available cores=4` 仅表示某次原生调用读回四个可用核心，不能证明三个视频线程分别完成了设置，也不能证明此前的允许范围已扩大。

小米 5 的 ADB 实测中，三个视频线程的 `Cpus_allowed_list` 均为 `0-3`，并观察到跨核心运行。连续拖动地图约 27 秒时，主要视频统计窗口的接收和提交速率约为 39–42 FPS，尚不能认定达到稳定 60 FPS，或把改善归因于亲和性改动。

日志写入线程在该次采样中占用约 0.27% 的单核 CPU；此数值不包含全部日志调用开销。此改动不替代对视频到达间隔、分辨率、解码和实际屏幕呈现的分析。

本次按用户确认保留已测试的 0.3.16 运行代码；逐线程设置和逐线程诊断的修正留待后续单独验证。
